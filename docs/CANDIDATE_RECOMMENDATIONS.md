# Candidate recommendations

Publication **2026-10-28.1** adds the [Candidate recommendations reader](../recommendations.html):
one recommended candidate per confirmed race, or an explicit no-recommendation where the
evidence does not support one.

## Rules

For each race in the current dataset (539 evaluated races: 471 confirmed on the November
ballot, 68 recorded but confirmed not on it), in order:

1. **Muslim community first.** A candidate whose Muslim-community membership is confirmed
   in the [community-observations registry](../research/candidate-community/observations.json)
   (12 races) is recommended outright; the card states "Confirmed member of the Muslim
   community."
2. **Jev decides.** Otherwise, the Jev decision model
   (`typesafe-ai/decision-2025-06`, via the Typesafe Jev API) reads each graded
   candidate's name, party, and published letter grade from the [pro-Palestine score
   publication](PUBLISHED_GRADES.md) plus the race context and picks the candidate to
   support (141 races). Single-candidate rosters are short-circuited locally at 100%
   confidence without a model call. The model's choice is archived with confidence,
   request hash, and timestamp; a different answer is never silently overwritten.
3. **No grades → no information.** Races where no candidate has a political grade
   (284 races) display "No recommendation due to a lack of information about this race."
4. **Only sub-C grades → no known good candidate.** Races whose graded candidates all sit
   below a C (102 races) display "No recommendation due to a lack of known good
   candidates."

Jev never sees raw evidence; it chooses from the published grades only.

## Summaries

Each recommended candidate (153) carries a "Why" paragraph generated by
`qwen/qwen3.8-27b` (temperature 1.0, thinking enabled, concurrency 2) from the same
evidence the grades were built from — the candidate's frozen record, published grade,
endorsements and opposition, Gaza evidence, campaign finance, and campaign platform —
with a strict factual-accuracy prompt: no invented records, quotes, endorsements, or
positions; no fabricated names, dates, or numbers; candidate-specific content only.
Summaries are archived in `research/candidate-recommendations/summaries-2026-10-28.jsonl`
with model provenance and word counts.

## Reproduce

```sh
python3 scripts/build_recommendations.py classify   # community + grade gates
python3 scripts/build_recommendations.py jev        # Jev picks (cached, resumable)
python3 scripts/build_recommendations.py summarize  # Qwen "why" paragraphs (cached)
python3 scripts/build_recommendations.py build      # emit recommendations.html
node tests/test-recommendations-display.node.cjs    # display regression
```

Jev requires the `JEV_API_KEY` environment variable (or `--jev-key-file`). Cached answers
are keyed by exact request, so rule or roster changes trigger only the affected calls.

## Limits

- Recommendations inherit the grade publication's evidence base: a candidate marked N/A
  there is invisible to the Jev decision.
- "Muslim community" uses the owner-curated registry only; no web-discovered claims are
  used for the recommendation itself.
- The reader is display-only; all decisions are pre-computed and archived.
